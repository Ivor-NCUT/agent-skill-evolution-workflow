# Skill 冲突审计

1. 比较 frontmatter 触发语、输入、输出和禁止事项。
2. 区分可调和重叠、必须隔离的业务差异和纯重复实现。
3. 用一个稳定 tie-breaker 解决相邻边界；相同能力保留一个事实源。
4. 检查父路由是否复制专家方法或两个父路由竞争。
5. 涉及 Skill 或 Agent 文档时，读取
   [Agent 文档设计](../agent-skill-evolution-workflow/references/agent-document-design.md)，
   检查弱触发指针、重复事实源、可从环境直接查询的缓存型说明和没有完成标准的步骤。
6. 重点检查授权继承、澄清时独立工作、审批范围、专家返回后的连续执行，以及测试和交付的停止条件。不要把查询事实的“确认”、接口前置条件或真实高风险授权误删。
7. 模型专项优化先核实该模型当前官方指导；区分官方特性、当前运行时能力和待验证假设，不凭“更强”推导无限授权或更少验收。
8. 输出冲突表、裁决、兼容影响和路由用例；用户要求优化时直接完成已授权本地修复与验证，不只交付审计方案。

不因名称相似就合并，不因来源不同就复制同一规则。
